# Архитектура проекта

Документ описывает внутреннее устройство системы распознавания российских автомобильных номеров: модули, пайплайн, форматы данных и ключевые решения.

## Модули

### 1. `src/detect.py` - Детекция номеров

**Назначение:** найти номерной знак на изображении и вернуть его вырезанную область.

**Класс:** `PlateDetector`

```python
class PlateDetector:

        self.model = YOLO(model_path)

    def detect(self, image_path: str, padding: int = 5):
        # Возвращает: (img, detections)
        # detections = [(crop, (x1, y1, x2, y2), confidence), ...]
```

**Ключевые решения:**
- **YOLOv8n** (nano) - выбран за баланс скорости и точности (mAP50 = 0.988).
- **Padding = 5px** - добавляется вокруг bounding box, чтобы не срезать края символов.
- **Фильтрация пустых crop'ов** - если вырезанная область пустая, она пропускается.

**Выход:** список кортежей `(crop, bbox, confidence)`, где `crop` - numpy-массив BGR.

### 2. `src/preprocess.py` - Предобработка

**Назначение:** подготовить вырезанный номер к подаче в OCR.

**Функция:** `preprocess(crop, target_h=80)`

**Шаги:**
1. **Увеличение** - если высота номера < 80px, увеличиваем с `INTER_CUBIC`.
2. **Grayscale** - для номеров достаточно серого канала.
3. **CLAHE** (`clipLimit=2.0`) - адаптивное выравнивание гистограммы для локального усиления контраста.
4. **Unsharp Masking** (опционально) - повышение резкости для размытых номеров.
5. **Конвертация обратно в BGR** - PaddleOCR ожидает 3-канальное изображение.

**Ключевые решения:**
- **Отказ от бинаризации** - Оцу-порог часто «съедает» символы на засвеченных/размытых номерах. Grayscale + CLAHE работает стабильнее.
- **Высота 80 px** - эмпирически подобранный размер, достаточный для OCR, не слишком большой для скорости.

### 3. `src/ocr_engine.py` - OCR + постобработка

**Назначение:** распознать текст на номере и привести его к формату РФ.

**Класс:** `PlateOCR`

**Инициализация:**
```python
self.ocr = PaddleOCR(
    lang='ru',                          # кириллическая модель
    use_doc_orientation_classify=False,
    use_doc_unwarping=False,
    use_textline_orientation=False,
    enable_mkldnn=False,
)
```

**Метод `read(image)`:**
- Подаёт изображение в `PaddleOCR.predict()`.
- Возвращает сырую строку (например, `'0364KP54.RUS'`).

**Метод `parse(raw_text)`:**
- Нормализует латиницу → кириллица (`A→А`, `B→В`, `O→О`).
- Очищает: только буквы `АВЕКМНОРСТУХ` и цифры.
- Берёт **первые 6 символов** — main-часть.
- Посимвольно корректирует:
  - Позиции 0, 4, 5 → буквы (с заменами `0→О`, `8→В`, `1→Т`).
  - Позиции 1, 2, 3 → цифры (с заменами `О→0`, `В→8`, `Т→7`).
- Всё после 6 символов → регион (2–3 цифры).
- Отбрасывает `RUS`, `/`, `.` и прочий мусор.

**Ключевые решения:**
- **Посимвольная коррекция** - формат РФ строго определён (`[БУКВА][3 ЦИФРЫ][2 БУКВЫ][РЕГИОН]`), поэтому мы знаем, что должно быть на каждой позиции.
- **Таблицы замен** - `DIGIT_TO_LETTER` и `LETTER_TO_DIGIT` для типичных ошибок OCR, когда буква принимается за цифру и наоборот (`O↔0`, `B↔8`, `T↔1`).

### 4. `src/main.py` — Связка модулей

**Назначение:** объединить детекцию, предобработку и OCR в один вызов.

**Функция:** `process_image(image_path)`

```python
def process_image(image_path):
    detector = PlateDetector(MODEL_PATH)
    ocr = PlateOCR()
    
    img, detections = detector.detect(image_path)
    results = []
    
    for crop, bbox, conf in detections:
        processed = preprocess(crop)
        raw_text = ocr.read(processed)
        plate, main_text, region_text = ocr.parse(raw_text)
        results.append({
            'plate': plate,
            'bbox': bbox,
            'detection_conf': conf,
            'raw_text': raw_text,
        })
    
    return img, results
```

## Ключевые решения и компромиссы

### Почему YOLOv8n, а не YOLOv8s?

- **YOLOv8n** - быстрее, что важно для edge-устройств, mAP50 = 0.988 - этого достаточно для номеров.
- **YOLOv8s** — точнее, но медленнее. Это создает существенные ограничения для работы на NPU.

### Почему PaddleOCR, а не EasyOCR/Tesseract?

| OCR | Точность на номерах | Скорость |
|-----|---------------------|----------|
| **PaddleOCR** | ~80% | Средняя |
| EasyOCR | ~60% | Медленная |
| Tesseract | ~13% | Быстрая |

PaddleOCR показал лучший результат на российских номерах «из коробки».

### Почему без бинаризации?

Оцу-порог работает хорошо на **чистых** номерах, но ломается на:
- Засвеченных.
- Размытых (особенно размытие в движении).
- С тенями.

Grayscale + CLAHE сохраняет все градации серого, и PaddleOCR сам решает, как их интерпретировать.

### Почему постобработка по позициям?

Формат РФ: `[БУКВА][ЦИФРА][ЦИФРА][ЦИФРА][БУКВА][БУКВА]`. Мы **точно знаем**, где буква, а где цифра. Это позволяет:
- Принудительно заменять `0→О` на позиции буквы.
- Принудительно заменять `О→0` на позиции цифры.
- Отбрасывать `RUS`, `/` и прочий мусор.
